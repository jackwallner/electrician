B2

Streak gains a day on a same-day session after the phone moves west

mediumconfirmedstate
Impact

The streak counter and the flame on Home go up by one for a day that was already counted. It repeats on every east to west move, so a traveller can inflate the streak by several days. It is cosmetic motivation data but it is the number the app celebrates.

How it happens
  1. Practise on Tuesday 10 Nov at 12:00 with the phone on New York time and finish one drill (streak 1).
  2. Fly or change the time zone to Los Angeles. It is now 10:00 on the same Tuesday.
  3. Finish a second drill.
  4. Streak reads 2 although only one calendar day has been practised.
Where
Shared/Services/ProgressStore.swift:62Shared/Services/ProgressStore.swift:66Shared/Services/ProgressStore.swift:67
Suggested fix

Store the day as a calendar day string or components (yyyy-MM-dd) instead of a midnight instant, and compare day strings. Or store the zone identifier with the instant and compute the stored day in that zone.

Evidence
let calendar = Calendar.current
let today = calendar.startOfDay(for: now)
let last = defaults.object(forKey: Keys.lastActiveDay) as? Date
if let last {
    let lastDay = calendar.startOfDay(for: last)
    let gap = calendar.dateComponents([.day], from: lastDay, to: today).day ?? 0
    if gap == 1 {
        streakCount += 1

lastActiveDay is saved as an instant, the local midnight of the zone the phone was in. That instant is 00:00 EST = 21:00 PST of the day before, so reading it again in the new zone and taking startOfDay lands on the previous day and the gap becomes 1. The reverse direction (west to east) does not misfire (control test passes). DST days do not misfire (controls pass).

Checked by: ProofTimeStateTests/testZ1_streakGrowsOnSameDaySessionAfterFlyingWest FAILED with streak 2, expected 1. Controls testZ3 (west to east), testD1 (spring forward) and testD2 (fall back) passed. Run repo-mbpro3cba5-1120-134908-28992 (GitHub Actions 44823660431).

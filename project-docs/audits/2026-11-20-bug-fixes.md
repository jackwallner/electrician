## Residual risks worth a device check

- **Android drift.** The Android port still writes `code-minute-rollup`, so it
  has the same B5 problem. (Its `ProgressStore.kt` already stores days as
  `LocalDate` strings, so B2 and B6 do not apply there.) `android/app/src/test/resources/electrician-parity.json` was not re-exported.
  That needs `swiftc` on a Mac: `python3 scripts/sync-android-content.py`. Then
  port the tracking ids to `EndlessPractice.kt`, or the Android parity test fails.
- **B2/B6 upgrade edge.** A day saved by an older build is read correctly when
  the phone is within 12 hours of the zone it was saved in. A user who upgrades
  right after flying further (New York to Tokyo, say) can see a one-time
  shift of a day. Every new session rewrites the value in the new format.
- **B3 on a restored phone.** On an install where iOS was never asked (a
  restored backup with a reminder on), the permission prompt now appears at
  launch. That matches the toggle the person set, but it is new behaviour. If
  notifications are later turned off in iOS Settings, the next return to the
  app switches the toggles off, and the "Notifications are off" alert shows the
  next time Settings or Exam Warm-Up is open. Real backup restore not run.
- **B8** needs a purchase killed mid-flight on a device to see the real path.
  The test forces membership with the DEBUG override.
- **B10** with a real banner tap while Settings is open. The test drives the
  same router call.
- **AX5 footer links.** At AX5 the paywall and trial link labels break inside
  words ("Resto/re", "Priva-/cy"). That is pre-existing and happens docked too.
- **Exam Target bar.** It now shows a back chevron beside Cancel. That is the
  held product call (Back keeps edits, Cancel discards them), unchanged here.

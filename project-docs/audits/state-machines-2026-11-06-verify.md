## Notes

- **B1, RevenueCat offline entitlements.** On a RevenueCat server error the SDK builds `CustomerInfo` from StoreKit's current entitlements with `requestDate: Date()` (purchases-ios `CustomerInfo+OfflineEntitlements.swift:47`), and that counts as current here. For an App Store subscriber StoreKit lists the subscription, so the answer is right; the base true-to-false handler already acts on the same answer. Only an entitlement granted outside StoreKit (a RevenueCat promotional grant) during an outage, after more than 3 days away, could be misread. No such grants exist in this repo's scripts. Not a check 4 breach: the answer is StoreKit's current record, not a cached or inferred state.
- **B1, clock skew.** `isCurrentAnswer` compares the device clock with the server's `requestDate`; a device clock days behind would make a stale cache read as current. Rare; no change needed now.
- **B2, Settings path.** A refusal from the Settings Daily Reminder toggle also arms the retry, so allowing notifications later in that session turns the reminder on. That matches the alert's own "Open Settings" route. No flow changed.

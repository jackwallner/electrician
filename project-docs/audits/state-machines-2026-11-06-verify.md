## Notes

- **B1 offline-entitlement edge.** When RevenueCat's backend is down (5xx), the SDK builds `CustomerInfo` from StoreKit's current entitlements (`CustomerInfoResponseHandler.swift:65-89`), and that answer counts as current. For a lapsed member StoreKit lists nothing, which is correct. A paying member is affected only if the product-to-entitlement mapping were wrong. The base `isPro` true-to-false handler already trusts the same answers.
- **B1 clock skew.** `isCurrentAnswer` compares the device clock with RevenueCat's server `requestDate`. A device clock running days behind would make a stale cache read as current. This is a rare edge, and no change is needed now.
- **B2 Settings path.** A refusal from the Settings toggle also arms the retry, so allowing notifications later in the same session turns the reminder back on. That matches the "Open Settings" alert there. No flow changed.
- **`testB4_cancelLeavesAbsentEditionKeyAbsent`** asserts that the edition reloads as `.nec2023`, not that the key is absent. Restoring a changed edition writes `nec2023`. It resolves to the same value, so users see no difference.
